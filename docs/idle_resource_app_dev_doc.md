| 决策项 | 选定方案 |
|---|---|

## 1. 产品定义

### 1.1 一句话
每天定时遍历已验证的公开资源平台，按"企业 / 个人"两类视角筛出有用、性价比高的在挂标的，推送给用户，并在 Android App 里可浏览、可筛选、可收藏。

### 1.2 用户分层与资源分类（核心设计）

用户要求从**客户角度**把标的分两类。这是整个筛选与评分的分水岭：

| 类别 | 目标用户 | 对应资源类型 | 主要来源平台 | 资金量级 |
|---|---|---|---|---|
| **企业类（B）** | 企业主、投资人、开发商 | 土地（一级/二级）、矿业权、厂房、企业整体资产、股权/债权、大宗产权 | 土地二级市场、矿业权市场、e交易（GQ/ZQ/TD/FC大宗）、公共资源交易 | 数十万～数亿 |
| **个人类（C）** | 普通个人 | 住宅房产、二手车、二手设备、闲置资产、小额招租 | e交易（CL/ESSB/WZ/小额FC/FCZZ）、司法/破产拍卖（后续） | 数千～数百万 |

> 分类不是靠平台，而是靠**标的类型 + 金额 + 用途**三个字段综合判定，见 §5.2 分类路由。同一平台（如 e交易）会同时产出两类标的。

### 1.3 MVP 范围边界

**做**：3 个平台的自动采集 + 统一入库 + 分类 + 评分 + 每日优选 + 机器人推送 + Android 浏览端。
**不做（本期）**：登录注册、订阅用户体系、需登录的平台（农村产权/林权/北交所）、验证码绕过、自动出价/报名。这些列入后续里程碑（§9）。

## 3. 数据源规格（全部实测）

### 3.1 全国土地二级市场 `market.mnr.gov.cn` — 企业类主力

**性质**：存量建设用地转让/出租/求购/成交公示。**接口完全开放，无需登录、无验证码**（本次最大发现）。

| 接口 | 路径（前缀 `https://market.mnr.gov.cn/api`） | 说明 |
|---|---|---|
| 转让信息 | `/epf-landweb/tsell/getTransfer` | GET，参数 `circulation=转让`、`pageNo`、`pageSize`、`cantonProvince`、`cantonCity`、`firstClassUse` |
| 求购需求 | `/epf-landweb/tpurchase/getIndexTPurchaseList` | GET |
| 热门供需 | `/epf-landweb/tlandSearch/getListPopular` | **坑：`pageSize` 被服务端锁为 2，翻页会重复，必须按 ID+标题去重** |
| 成交公示 | `/epf-landweb/landweb/transtarget/transNoticeOrResultList` | 字段名为 `publictTitle`/`transPrice`/`insertTime`（与其他接口不同） |

**返回结构**：`{code:0, pager:{results:[...], totalRecord, totalPage}}`

**核心字段**：`title`、`cantonProvinceName`、`cantonCityName`、`cantonAreaName`、`firstClassUseName`、`circulationName`、`area`、`useYear`、`price`、`sellerName`、`releaseDate`、`id`

**实测样本**：长沙县 10 亩工业用地 + 3600㎡房产 **580 万**；哈尔滨双城区 3 万㎡工业用地 **3500 万**；喀什 81.6 亩商住用地 1.33 亿。当前在挂转让约 15 条——**低频市场，属正常，不要误判为抓取失败**。

**已实现脚本**：`collect_market_mnr.py` → `output/market_mnr_listings.csv`（去重后 44 条）。

### 3.2 矿业权市场 `ky.mnr.gov.cn` — 企业类特色

**性质**：探矿权/采矿权出让 + **转让公示（矿主出手线索，最有价值）**。静态 HTML + `index_N.html` 分页，极稳定。

| 栏目路径（base `https://ky.mnr.gov.cn/`） | 类型 |
|---|---|
| `kyqcrgg/tkq/` | 探矿权出让公告 |
| `kyqcrgg/ckq/` | 采矿权出让公告 |
| `zrgs/tkzrgs/` | **探矿权转让公示** |
| `zrgs/ckzrgs/` | **采矿权转让公示** |
| `jggs/jjgs/` / `jggs/ckjjgs/` | 出让结果 |

**解析规则**：链接正则 `t20\d{6}_\d+\.htm`，日期从 URL 的 8 位数字提取；列表页字段仅"类型/标题/日期/链接"，**详情需二次抓取**。

**实测**：287 条，其中转让公示 99 条。样本：赤峰翁牛特旗铅锌矿勘探转让、河南嵩县金矿详查转让、建德市砂岩矿采矿权转让。

**已实现脚本**：`collect_ky.py` → `output/ky_notices.csv`。

### 3.3 e交易 `ejy365.com` — 企业类 + 个人类双产出

**性质**：国资产权交易平台。列表静态可抓，详情静态可抓，robots 允许 `/info/` 与列表页。

**列表**：`https://www.ejy365.com/jygg_more`，参数 `project_type`（28 种）、`area_code`、`status=START_BM`、`orderType=orderType2_up`（低价）/`orderType1`（默认）、`page`（每页 16 条）。卡片在 `<div class="product-list">#cqjyUl` 的 `<li>`；挂牌价在 `span.fcdd3` 的 `title` 属性；城市在 `onclick updateTypeCookieAndOpenPage` 第 4 参。

**品类代码**：`FC` 房地产、`CL` 二手车、`ESSB` 二手设备、`WZ` 闲置资产、`FCZZ` 招租、`GQ` 股权、`ZQ` 债权、`TD` 土地等。

**详情**：`/info/{code}`。评估价在"评估价（元）"表格行，保证金在 JSON-LD 的"交易保证金"，建筑面积在 `class="subAssetName">房屋建筑面积` + `class="money small" title`。转让底价 = 挂牌价。

**实测**：1232 条在报名标的，58 条有评估价，170 条有建筑面积。

> **重要认知**：国资产权交易**挂牌价≈评估价，不能贱卖**，最低折扣仅 0.80（二手车），没有司法拍卖那种 0.5 折房产。真正的"划算"来自：①低于评估价的二手车/设备；②二次挂牌（流拍降价史）；③单价偏低且在主城区的住宅。87% 标的由产权交易所/拍卖行挂牌（可靠性较高），但平台声明不担保瑕疵。

**已实现脚本**：`collect_ejy.py`（列表）、`collect_ejy_detail.py`（详情，8 线程并发 17 秒）、`collect_ejy_house.py`（房产）、`rank_ejy.py`（评分）。

### 3.4 公共资源交易 `ggzy.gov.cn` — 仅详情页样本

详情页静态可读：`/information/deal/html/a/{省码}/{业务码}/{日期}/{hash}.html`，14 条样本全部直连成功。列表页 JS 渲染，API `/information/pubTradingInfo/getTradList` 带验证码（code 829）和限流（code 800）——**不硬闯，本期只做样本**。

### 3.5 暂不接入的平台（附原因，避免重复踩坑）

农村产权（江苏域名已变 `jsnc.gov.cn`→`jtzc.jssny.com.cn`，明细在会员端需登录；成都/武汉/天津同样需登录）、林权（南方林权骨架屏、华东林权 502）、北交所（521）、上海联交所（项目列表 404）、京东拍卖（空壳）。这些**适合人工查，不适合公开抓取**。

## 4. 统一数据模型

### 4.1 归一化标的 Schema（所有平台收敛到此结构）

```json
{
  "id": "uuid",
  "source": "market_mnr | mining | ejy | ggzy",
  "external_id": "平台原始ID/链接hash",
  "category": "B | C",              // 企业 / 个人
  "asset_type": "土地 | 矿业权 | 房产 | 二手车 | 二手设备 | 闲置资产 | 股权 | 债权 | 招租",
  "title": "标的标题",
  "province": "省", "city": "市", "district": "区县",
  "area_sqm": 0,                     // 面积(㎡)，无则 null
  "price_yuan": 0,                   // 挂牌/转让价(元)，面议则 null
  "price_text": "580万元",           // 原文，供展示
  "appraisal_yuan": 0,               // 评估价，无则 null
  "unit_price": 0,                   // 元/㎡，可计算则填
  "discount_rate": 0.0,              // 挂牌价/评估价，<1 为低于评估
  "deadline": "2026-12-04",          // 报名截止
  "seller": "挂牌方",
  "seller_grade": "政府/国资 | 产权机构 | 金融 | 企业",
  "second_listing": false,           // 二次挂牌/流拍降价史
  "has_defect_note": false,          // 瑕疵提示
  "use_type": "工业 | 商住 | 住宅 | 采矿 | 探矿 | ...",
  "url": "原始链接",
  "published_at": "2026-11-23",
  "collected_at": "2026-11-24T07:31:00",
  "score": 0,
  "score_reasons": ["低于评估价15%", "二次挂牌", "挂牌方:政府/国资"],
  "raw": "{\"原字段\": ...}"          // 保留原始字段供核查
}
```

### 4.2 数据库表（SQLite 起步，够用；上量后迁 PostgreSQL）

| 表 | 主键 | 关键字段 | 用途 |
|---|---|---|---|
| `listings` | `id` | `source`, `external_id`(唯一索引), `category`, `price_yuan`, `score`, `url`, `collected_at` | 归一标的，`UNIQUE(source, external_id)` 去重 |
| `listing_changes` | `id` | `listing_id`, `field`, `old`, `new`, `changed_at` | 变更检测（降价/延期/新增），推送触发源 |
| `recommendations` | `id` | `date`, `category`, `listing_id`, `rank`, `score` | 每日优选结果 |
| `push_log` | `id` | `date`, `channel`, `status`, `detail` | 推送成败与幂等（同日不重复推） |
| `sources` | `name` | `last_run`, `status`, `item_count` | 采集器健康状态 |

后续扩展表（§9）：`users`、`subscriptions`、`user_filters`、`favorites`（收藏也可先存 App 本地 Room）。

## 5. 分类与评分引擎（核心逻辑）

### 5.1 设计原则
- **分而治之**：企业类看"权属/用途/规模/合规风险"；个人类看"折扣/单价/可靠性/可负担"。同一条标的两套权重分别打分，取所属类别的那套。
- **诚实打分**：国资产权平台不虚构捡漏；"便宜"若来自偏僻位置/瑕疵/难变现，要扣分而非加分。
- **可解释**：每条推荐附 `score_reasons`，用户能看到为什么被选中。

### 5.2 分类路由（Classifier）

按优先级判定：
1. `asset_type ∈ {土地, 矿业权, 股权, 债权}` → **B**
2. `asset_type = 房产` 且 `price_yuan ≥ 300万` 或用途为工业/商铺/整栋 → **B**；否则 → **C**
3. `asset_type ∈ {二手车, 二手设备, 闲置资产}` → **C**
4. `asset_type = 招租` → 按金额与用途二次判定（大额厂房→B，小额商铺/住宅→C）

> 金额阈值（300 万）已确认；仍做成 `config.yaml` 可调项，方便后续微调。全国全量，不做地域过滤。

### 5.3 企业类（B）评分权重（满分 100）

| 维度 | 规则 | 分值 |
|---|---|---|
| 权属清晰 | 出让（非划拨）、有证 | +20 / 划拨 -10 |
| 用途匹配 | 工业/商住符合订阅用途 | +15 |
| 规模合适 | 面积落在订阅区间 | +10 |
| 价格合理 | 有评估价且低于评估，或单价低于同城基准 | +20 |
| 合规风险 | 无抵押/查封/在租 | +15 / 有 -15 |
| 生态/规划义务 | 无矿坑治理、土壤污染义务 | +10 / 有 -20 |
| 挂牌方可靠 | 政府/国资/产权机构 | +10 |
| 时效 | 报名剩余 ≥ 7 天 | +5 |

### 5.4 个人类（C）评分权重（满分 100）

复用已验证的 e交易规则（`rank_ejy.py`），归一化到百分制：

| 维度 | 规则 | 分值 |
|---|---|---|
| 折扣率 | ≤0.85 +30；≤0.95 +18；≤1.0 +8；>1.2 −15 | 折扣分档 |
| 住宅单价 | 单价 < 5000 元/㎡ **且确为住宅**（排除车库/商铺/厂房/经营性房产） | +20 |
| 二次挂牌 | 有流拍降价史 | +12 |
| 挂牌方 | 政府/国资 +9；产权机构/金融 +6；企业 +3 | 分级×3 |
| 时效 | 报名剩余 ≥ 3 天 +5；已截止 −20 | 时效分 |
| 瑕疵提示 | 有瑕疵 | −3 |

> **踩过的坑（务必保留）**：①住宅判定要排除"车库/车位/商铺/商业/经营性/厂房/仓库/写字楼/市场/门店/工业/车间/商住楼"；②"二次挂牌"只能在标题里匹配，否则会命中页面通用提示文字导致全判 1；③金额解析要容忍"面议/无价"，不要抽到"1 元/吨废铁"这类按吨计价的废旧物资。

### 5.5 每日优选（Selector）
- 每类取 Top-N（默认各 10 条，可配置）；
- **变更优先**：`listing_changes` 中"降价 / 新挂牌 / 延期"的标的权重提升，即使总分不最高也进入推送；
- **去重**：同标的 ID 当天只推一次（`push_log` 幂等）；
- **冷启动**：首日全量推荐，次日只推新增 + 变更 + Top 榜变动。

## 6. 服务端实现

### 6.1 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.11 | 复用已写的采集脚本（`urllib` + `re` + `csv`，零第三方依赖） |
| 调度 | APScheduler 或系统 cron | 简单可靠，每日 07:30 全量跑一次 |
| HTTP 客户端 | `requests` + 并发 `ThreadPoolExecutor` | e交易详情已验证 8 线程 17 秒完成 |
| 存储 | SQLite（起步）→ PostgreSQL | 单用户 SQLite 足够，多用户再迁 |
| API | FastAPI | 自动生成 OpenAPI 文档，App 对接方便 |
| 部署 | 云托管：云数据库存数据 + WorkBuddy 定时任务触发采集 | 已确认方案，详见 §6.4 |

### 6.4 云托管部署方案（已确认）

**必须讲清的一个事实**：WorkBuddy 云服务提供 **数据库 / 认证 / 存储 / LLM** 四个模块，但**它本身不提供"每天定时跑 Python 采集脚本"的服务器端 cron 或定时函数**。所以完整的托管链路是"云上存数据 + WorkBuddy 定时任务负责调度"两者组合，而不是单纯一个云数据库。

| 需求 | 用什么承载 | 说明 |
|---|---|---|
| 标的/推荐/推送日志持久化 | **WorkBuddy 云数据库** | 把 §4.2 的 `listings`/`recommendations`/`push_log` 存进去；App 通过 SDK 读取，免密钥、免自己运维数据库 |
| 每天 07:30 触发采集 | **WorkBuddy 定时任务（automation）** | 建一条 recurring 自动化，每天调一次：跑 3 个采集脚本 → 评分 → 写云数据库 → 触发推送 |
| 新增/降价即时补推 | 同一条定时任务内做变更检测 | `listing_changes` 有变更就即时推；做到"定时+变更即推"而不用常驻进程 |
| 机器人 / Server酱推送 | 定时任务里调 Webhook | sendkey/Webhook 存服务端配置，不进代码库 |
| App 读数据 | Kotlin App 内集成云数据库 SDK | 初始化用 `endpoint` + `publishableKey`（来自 `publicConfig`），不要硬编码域名 |
| 后续订阅用户（M3） | 云服务 **Auth 模块** | 与云数据库同环境，按用户对数据做隔离 |
| 标的摘要/风险提示（可选） | 云服务 **LLM 模块** | 免密钥调用，给标的自动生成一句话摘要 |

**约束与注意**：
- 一个 App 只对应**一个**云环境，数据库/认证/存储/LLM 共用它，不要按模块分多个环境。
- 定时任务依赖会话/调度器常开能力；若运行环境不能保证每天触发，降级为自有小主机 cron 或 GitHub Actions cron，写库逻辑不变（只换触发方式）。
- 密钥（Webhook、sendkey）放服务端配置，前端只有 `publishableKey`（本身无权限，靠 Origin 校验），不要把任何长期密钥写进 App 代码或日志。
- 采集频率礼仪不变：每站每请求间隔 ≥ 0.2s、每日单站控制在数百次内、不登录不绕验证码。

> 现在文档阶段**不实际开通**云服务；进入 M1 编码、真正需要写库时再由 WorkBuddy 的可信确认界面开通环境（会有明确的授权确认，不会自动扣费）。

## 7. 推送设计（MVP）

### 7.1 通道（零成本起步）
- **企业微信/钉钉群机器人**：Webhook URL，POST Markdown 消息；
- **Server酱**：`https://sctapi.ftqq.com/{sendkey}.send`，推送到微信；
- 两者可同时配，互为备份。sendkey/Webhook 存服务端配置，不进代码库。

### 7.2 消息格式（示例）

```
## 每日资源优选 · 2026-11-24
**企业类 Top3**
1. [长沙县10亩工业用地+3600㎡房产](url) — 580万 · 评分88
   理由：低于评估价12% · 工业用途 · 国资挂牌
2. ...
**个人类 Top3**
1. [徐州泉山区玉兰雅苑 105.91㎡](url) — 42.6万 · 4024元/㎡ · 评分76
   理由：主城区住宅 · 低单价 · 报名剩10天
...
（今日新增 12 条 · 降价 3 条 · 点开 App 查看全部）
```

### 7.3 幂等与失败处理
- 按 `date + channel` 写 `push_log`，当天已推则不重复；
- 推送失败重试 2 次，仍失败则记录并在下次调度补发摘要；
- 消息内链接指向服务端 H5 详情或 App 深链（深链后续）。

### 8.3 关键交互
- 推荐卡片显示**评分 + 标签**（如"低于评估价12%""二次挂牌""国资"），让可解释性直达用户；
- 详情页固定展示**风险提示卡**（国资产权不担保瑕疵、矿业权有生态修复义务等），避免误导；
- 原始公告用浏览器打开，不在 App 内套壳（避免链接失效/跳转问题）。

### 8.4 MVP 与服务端的关系
MVP 阶段 App 是**只读展示端**：数据全部来自服务端 API，推送走机器人。App 首次打开拉取当日推荐，本地 Room 缓存。这样即使 App 未安装，推送也能到达——符合"先跑通推送闭环"的目标。

## 10. 风险与合规

1. **数据真实性**：平台声明不担保瑕疵，评估价仅供参考；所有推荐必须附原始链接，用户自行尽调。
2. **必查五项**（详情页/推送里提示）：权属（出让/划拨、有无证）、规划用途与控规、能否分割过户、有无抵押/查封/在租、环保与地质（土壤污染、矿坑治理）。
3. **采集礼仪**：只抓公开数据；遵守 robots；控制频率；不登录、不绕验证码、不传用户账号密码。
4. **接口稳定性**：政府站接口可能变更（如江苏农交所域名已变），需给每个 Adapter 加健康监测与告警，失败不影响其他平台。
5. **误判风险**：低价可能来自偏僻位置/瑕疵/难变现，评分要体现"便宜≠划算"。
